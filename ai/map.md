# Repo map

Navigation only: where things live and who owns what. How it works is in the code, why in `ai/decisions/`.

## Repo

- `src/` — every source. `dist/` — the build output, generated by `npm run build`; never edited.
- `package.json` — the scripts (`check` is `minista check`, `size` is size-limit);
  `vite.config.js` — only re-exports `vite/config.js`, which builds the config from `vite/parts/` (one `get…`
  per concern: `aliases`, `plugins`, `image`, `css`, `build`); `vite/paths.js` — the paths; `vite/constants.js` — the
  constants the build plugins share; `vite/plugins/` — build plugins: `source-type`, and `site-files` (helpers in `vite/site-files/`) that emits
  `robots.txt`, `sitemap.xml` and `llms.txt` from the built pages; `vite/postcss/` — the PostCSS plugins `fluid`, `hover`, `breakpoints`.
- `.prettierrc`, `.prettierignore` — Prettier. `eslint.config.js`, `.stylelintrc.json` — ESLint and Stylelint.
  `.husky/pre-commit` and `.lintstagedrc.json` — the pre-commit hook that runs them on the staged files.
- `.github/workflows/ci.yml` — the checks on every push. `.size-limit.json` — the budget of the built JS, CSS, fonts and images.
- `.vscode/` — `css-data.json` tells VS Code about `@tablet` and `@mobile` (decision `vscode-css-data`).
- `jsconfig.json` — the editor's copy of the aliases `vite/parts/aliases.js` defines, `@<folder>` for each `src/` folder
  (`@components`, `@sections`, `@utils`, `@data`, `@constants` are barrels, imported bare).
- `src/pages/` — one JSX file per page, its file name is its URL: Home (`/`), News, Podcasts, Resources, Contact, 404 (`sections/not-found/`), and `/ui`, the UI kit demo (noindex, linked from nowhere).
  A page exports `metadata = pages.<name>` (from `data/pages.js`) and its content, no head.
  `pages/blog/[slug].jsx` is the article route: `getStaticData` makes one page per entry of `data/posts.js` at `/blog/<slug>`
  (`getPostUrl`); it passes the post's title and excerpt as the page's title and description.
- `src/layouts/` — the shell of every page: `<html>`, the head (title, script, `components/head/` fed with the page's
  `metadata`, `url` and `post`), `<main>`;
  the header, the CTA (`CtaRevolution`) and the footer join it from `sections/shared/`.
- `src/sections/` — one folder per section (JSX, stylesheet, `index.jsx`, a folder per part), by page group (`home/`, `news/`, …,
  `ui/`; `shared/` when two pages use it); `sections/index.jsx` re-exports the groups.
  `shared/Header` is on every page: the skip link, the newsletter strip, the navbar and the mobile menu (decision `mobile-menu-drawer`).
  `shared/VideoModal` is the one `<dialog>` the layout renders on every
  page; any `[data-video-id]` button opens it.
- Home sections (`sections/home/`), in design order on `pages/index.jsx`: `Hero` (the page's `h1`, the eyebrow, three
  stats, the avatar capsule with the link to Resources, three feature links, `HeroFeature`),
  `Features` (id `features`: the heading band and two `FeatureGroup`s, each beside a 2 x 2 grid
  of `FeatureCard`s), `Blogs` (id `blogs`: `SectionHeading` and a `PostFeed` of the `blogs` posts), `Resources` (id `resources`:
  `SectionHeading` and two `ResourceShowcase`s, Ebooks and Whitepapers),
  `Testimonials` (id `testimonials`, the last section: `SectionHeading` with the "View All Testimonials" button that
  drives `Disclosure` below 768px, and six `TestimonialCard`s in two `TestimonialGroup` lists, the second one the
  `Disclosure` region).
- News sections (`sections/news/`), in design order on `pages/news.jsx`: `NewsIntro` (the `PageIntro` of News), `FeaturedNews` (the `featured`
  post: photo, title, text, `MetaGrid`, counters, Read More), `TrendingStories` (id `trending-stories`: three `NewsCard`s, a hidden `h2`),
  `NewsHub` (id `news-hub`: a `PostFeed` of the `headlines` posts),
  `FeaturedVideos` (id `featured-videos`: the `videos` as a 2 x 2 list of `VideoCard`s split by lines).
- Podcasts sections (`sections/podcasts/`), in design order on `pages/podcasts.jsx`: `PodcastsIntro` (the `PageIntro` of Podcasts),
  `TopPodcasts` (id `top-podcasts`: one `PodcastShow` per show of `podcasts`: host plate with Listen Podcast
  beside the video preview, lead text and `MetaGrid` stats), `LatestPodcasts` (id `latest-podcasts`: `SectionHeading` with the "View All
  Episodes" button that drives `Disclosure` below 768px, and six episode `VideoCard`s in two `EpisodeGroup` lists, the second one the region).
- Resources sections (`sections/resources/`), in design order on `pages/resources.jsx`: `ResourcesIntro` (the `PageIntro` of Resources),
  `ResourceStats` (id `resource-stats`: the four large `Stat`s of `stats`, a hidden `h2`),
  `ResourceLibrary` (id `resource-library`: `SectionHeading` with the Whitepapers / Ebooks / Reports tabs, one `ResourcePanel`
  per tab, a `ResourceRow` per resource: intro, photo, download, `MetaGrid`),
  `ResourceCards` (id `resource-cards`, the last section: a hidden `h2` and three `ResourceCard`s of `resourceCards` split by
  lines, each with "View Details" to its tab and the download button).
- Blog sections (`sections/blog/`), on `pages/blog/[slug].jsx`: `Article` (root `data-article`): `ArticleHero` (the photo and the page's `h1`),
  then `ArticleBody`: one `ArticleSection` per `body` entry (its `id` is the anchor; the first is the lead), the sections after the first
  `previewCount` in a `Disclosure` region behind "Read Full Blog" over a fade. `ArticleController` owns it.
  `ArticleSidebar` (the second grid column from 1024px): large `CounterPill`s (the like is a toggle), the 2 x 2 `MetaGrid`
  with the reading time. Then `SimilarNews` (three `NewsCard`s from `getSimilarPosts`). Texts: `data/article.js`.
- Contact sections (`sections/contact/`), in design order on `pages/contact.jsx`: `ContactInfo` (id `contact-info`: the page's
  hidden `h1` and four `ContactColumn`s of `contacts`, each with `ContactLinks`, `ContactOffice` or `ContactSocials`),
  `ContactForm` (the `<form id="contact-form">` beside the icon and `h2`: a field part per kind, `ContactFormController` checks it,
  the phone field is a flag box over a native country `<select>`; countries in `data/countries.js`),
  `Faq` (id `faq`: the "Ask Question" link to the form, beside one `FaqItem` per question of `faq`, each
  its own `Disclosure`, the first open).
- `public/` — fixed-URL files copied as they are: `favicon.svg`, `favicon.png`, `og-image.png` (1200 x 630); the build
  adds `robots.txt`, `sitemap.xml` and `llms.txt` (decision `seo-files-and-structured-data`).
- `src/components/` — repeated elements as JSX, one folder each (`ui/Button/`: `Button.jsx`, `Button.css`, `index.jsx`),
  in groups by role with an `index.jsx`; `components/index.jsx` re-exports the groups.
- `components/head/`: the head's parts (`FontPreloads`, `SeoMeta`, `SocialMeta`, `JsonLd` with `utils/get-*-json-ld.js`, …).
- `components/media/`: `Icon` renders a sprite icon (`name` is its path under `assets/icons/`), `Photo` an optimized photo.
- UI kit (`components/ui/`): `Button`, `Tag`, `Badge`, `SectionHeading`, `Stat`, `MetaItem` and `MetaGrid`, `CounterPill`,
  `AvatarGroup`, `PlayButton` (opens the video modal), `Heading`. `/ui` shows each in every variant.
- Cards (`components/cards/`): `NewsCard` and `VideoCard` (`isEpisode` adds Listen Podcast, which opens the same video). Both are on `/ui`.
- Where the key buttons lead: Download PDF Now, the newsletter strips and Community Forum to `/contact`; Home's Download Ebooks /
  Whitepapers Now and Preview to that tab of `/resources`; View All to the page that lists more (News's to the Home blog feed);
  play, Listen Podcast and the article's like are buttons, card likes are counters.
- `PageIntro` (`components/page/`): the page's `h1` over two lines with the text beside the second one (stacked at
  390); News (with the taller `isSpacious` bottom), Podcasts and Resources render it from their data; 404 puts its button under the text.
- `PostRow` (cards) and `PostFeed` (`components/feeds/`: the category
  tabs and the list of `PostRow`s, filtered in the browser by `PostFeedController`); both are on `/ui`.
- `src/data/` — the texts, ids and lists the components render, as plain exported values, one file per entity or
  section: `posts` (with their article `body`), `categories`, `videos`, `podcasts`, `resources`, `testimonials`,
  `features`, `stats`, `faq`, `navigation`, `footer`, `socials`, `contacts`, `contact-form`, `countries`, `cta`, `hero`,
  `blogs`, `news`, `not-found`, `article`, `post-feed`, `video-modal`, `card-photos` (photo `sizes` and widths), `ui-kit` (`/ui` demo
  lists), `pages` (each page's metadata) and `site` (the name, origin, locale, theme colour, icons, social image).
- `src/utils/` — pure build-time helpers, one function per file (`get-page-title.js`, `get-post-url.js`, …), re-exported by
  `index.js` (plain JS, no JSX), imported by components, sections and the layout.
- `src/constants/` — what utils and scripts share (formats, keys, selectors, media queries, storage keys, widget
  settings), one file per meaning, re-exported by `index.js`.
- `src/styles/` — global CSS only: `variables.css` (the tokens), `reset.css`, `base.css` (body, focus ring,
  `.container`, `.visually-hidden`), `reveal.css` (the scroll-reveal keyframes and hidden start state), `fonts.css`; `global.css` imports them, the layout imports it first.
  Components and sections import their own stylesheet; the build bundles all into one file.
- `src/scripts/` — all browser JavaScript: `main.js` (the one entry, loaded by the layout: a table of root hook →
  class, each root found is created and started), `components/` (the widgets `Tabs`, `Disclosure`, `Toggle`, `VideoModal`, `CountUp`, `FormField`, `LikeButton`, `Reveal`: root `<html data-reveal-root>`),
  `services/` (`StorageItem`, `VisibilityObserver`), `controllers/`
  (one per section: `HeaderController`, which runs the menu; `VideoModalController`, which opens the modal from any play button;
  `PostFeedController`, which filters a feed's rows by the selected tab; `ContactFormController`, which checks and completes the form;
  `ArticleController`, which runs "Read Full Blog").
- `src/assets/` — referenced by the build and emitted hashed: `fonts/` (woff2, `index.js`), `icons/` (sprite icons in `ui/`, `social/`,
  `feature/`, `flag/`; one sprite per folder), `logos/` (inline SVG: the logo and its mark), `images/` (`photos/`, `portraits/`, `decor/`).
- `AGENTS.md` — the entry point for agents; `CLAUDE.md` points to it.
- `ai/` — agent docs: this map, `workflow.md`, `rules/`, `skills/`, `decisions/`, `prompts/`,
  `linear-task-template.md`, the archive `superpowers/`, `design-system.md`.
- `.claude/worktrees/` — a git worktree per parallel task; git ignores it.

## Deployment

- Live site: <https://futuretech-cyan.vercel.app>, deployed by Vercel's Git integration.
- `main` is production, other branches get a preview; the config is `vercel.json`.

## Where is the recipe

- A page section or a repeated element: `ai/skills/section.md`. Reviewing a diff: `ai/skills/review.md`.
- Colours, type, spacing, components and the sections of each page, as designed: `ai/design-system.md`.
- What must hold: `ai/rules/`. Why it is so: `ai/decisions/` (index in its `README.md`).
- minista's own API: <https://minista.dev> and `minista agents` (`ai/rules/minista.md`).

## Not in this project

- What the project does not add is listed in `ai/rules/scope.md`. The decisions behind the main
  ones: `minista-jsx-static-html` (no React in the browser, no TypeScript), `no-automated-tests`,
  `local-merge-without-pr`, `contact-form-without-backend`.
