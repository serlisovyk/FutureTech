# Repo map

Navigation only: where things live and who owns what. How it works is in the code, why in `ai/decisions/`.

The source tree below is the agreed layout; the init task (MY-247) creates it and replaces this note with the
real structure.

## Repo

- `src/` — every source. `dist/` — the build output, generated by `npm run build`; never edited.
- `src/pages/` — one JSX file per page: Home (`/`), News, Podcasts, Resources, Contact, 404, and the article
  route that renders one page per blog post from `data/`.
- `src/layouts/` — the page shell shared by every page: `<html>`, the head, the header, `<main>`, the CTA, the footer.
- `src/sections/` — one JSX file per page section, by page (`home/`, `news/`, …; `shared/` when two pages use it).
- `src/components/` — repeated elements as JSX (a button, a card, a tag): props in, markup out.
- `src/data/` — the texts and lists the components render, as plain exported values.
- `src/styles/` — all CSS: tokens and base, shared UI elements, one stylesheet per component and section.
- `src/scripts/` — all browser JavaScript: `main.js`, `components/` (widgets), `controllers/` (sections).
- `src/assets/` — `fonts/`, `images/` (photos, icons, decor), referenced by the build and emitted hashed.
- `AGENTS.md` — the entry point for agents; `CLAUDE.md` points to it.
- `ai/` — agent docs: this map, `workflow.md`, `rules/`, `skills/`, `decisions/`, `prompts/`,
  `linear-task-template.md`, the archive `superpowers/`, and `design-system.md` (MY-246).
- `.claude/worktrees/` — one git worktree per task when tasks run in parallel; ignored by git.

## Where is the recipe

- A page section or a repeated element: `ai/skills/section.md`. Reviewing a diff: `ai/skills/review.md`.
- Colours, type, spacing, components and the sections of each page, as designed: `ai/design-system.md`.
- What must hold: `ai/rules/`. Why it is so: `ai/decisions/` (index in its `README.md`).
- minista's own API: <https://minista.dev> and `minista agents` (`ai/rules/minista.md`).

## Not in this project

- No React in the browser, no TypeScript, no backend or CMS: decision `minista-jsx-static-html`.
- No automated tests: decision `no-automated-tests`. No pull requests: decision `local-merge-without-pr`.
- No login or sign-up pages; forms send nothing to a server of the project's own (`ai/rules/scope.md`).
