# Plan: path aliases per folder

Issue MY-297, branch `my-297-aliases`. No observable behavior changes, so no spec: the output of the
build stays the same, only how the sources point at each other changes.

## Scope

- `vite.config.js` — `resolve.alias`; `jsconfig.json` — the same `paths` for the editor.
- Every import and `url()` that crosses folders in `src/`: the layout, the components, the scripts,
  `styles/fonts.css`.
- Docs: `ai/rules/jsx.md`, `oop.md`, `css.md` (one line each), `ai/map.md`, a decision record and
  its index line.

Not in scope: the minista asset components' `src`, moving or renaming any file, new folders.

## Aliases

| Alias         | Folder            |
| ------------- | ----------------- |
| `@components` | `src/components/` |
| `@sections`   | `src/sections/`   |
| `@layouts`    | `src/layouts/`    |
| `@data`       | `src/data/`       |
| `@styles`     | `src/styles/`     |
| `@scripts`    | `src/scripts/`    |
| `@assets`     | `src/assets/`     |

One alias per folder, not a single `@/`: the folder is named at the import (decision
`path-aliases`, written in this task). `src/pages/` has no alias: nothing imports a page.

## Decided

- **Config:** a local helper `src(folder)` resolves each path with
  `fileURLToPath(new URL(…, import.meta.url))`, so the config does not depend on the working
  directory and needs no `node:path`.
- **`jsconfig.json`:** `compilerOptions` with `baseUrl` and `paths` only (`paths` lives in
  `compilerOptions`); no `include`, `exclude`, `target` or `checkJs`.
- **Same folder stays relative:** `./Icon.css` in a component, `./components/Tabs.js` in
  `scripts/main.js`. An import crosses a folder when it climbs with `../`, so a sub-folder reaching
  the parent (`scripts/components/Tabs.js` → `constants.js`) uses the alias: `@scripts/constants.js`.
- **CSS:** Vite resolves aliases in `@import` and `url()`; `fonts.css` font `url()` and the
  `global.css` import switch to the aliases if the build bundles the fonts as before, otherwise the
  relative path stays and the reason is recorded.
- **minista asset components:** `Sprite`, `Svg` and `Picture` take root paths
  (`/src/assets/…`). Checked against minista.dev (the Sprite guide and plugin pages show only root
  paths, none mentions aliases) and the installed package: `pluginSvg` resolves a source with
  `path.resolve(rootDir, source.replace(/^\//, ''))`, not through Vite's resolver, and the sprite
  builder takes root paths too. Confirmed on the temporary page with an alias `src`; if it fails, the
  root path stays and is written in `jsx.md` as the one exception. minista's own aliases
  (`/@__minista-*`) are merged with ours (`mergeAlias` in the package), no clash.
- **`<script src="/src/scripts/main.js">`** in the layout is a root URL in the HTML head that minista
  rewrites to the hashed file, not an import: it stays a root path (checked on the build).
