- `pluginImage({ optimize, loading, decoding })`; components `Image` and `Picture` from
  `minista/assets`. `Picture` takes `formats` (the last one is the `<img>` fallback, the others
  become `<source>`s), `sizes`, `breakpoints`, `formatOptions`, `quality`; `width` and `height` are
  read from the file. Candidates larger than the source are not generated.
- `pluginSprite()` combines the SVG files of a directory into one `<dir-name>-<hash>.svg`; the file
  name is the symbol id; `Sprite` (`src`, `title`, SVG props) renders `<svg><use href=…#id/></svg>`.
- `pluginSvg()`; `Svg` (`src`, `title`, SVG props) inlines the file after SVGO; `class` and drawing
  attributes of the source are kept.
- `pluginBeautify` only **adds** indentation to the output: it is the opposite of minification. minista
  has no HTML minifier and no option for one (Vite minifies JS and CSS only).

   small module `vite/minify-html.js` (the custom plugin below), one concern per module under `vite/`.

4. **Assets** cleaned from the design into `src/assets/`: `logo.svg`, `logo-mark.svg`, the sprite icons

   pipeline. The catalogue of every other photo stays outside the repo.
5. **Docs:** `ai/map.md`, `ai/rules/{jsx,assets-performance,minista}.md`, the two records and their index

## Decided here

- **Formats and quality.** `Photo` renders `formats={['avif', 'webp']}`: AVIF `<source>`, WebP `<img>`
  fallback, no JPEG. AVIF quality 60, WebP 78 (`formatOptions` in the plugin); checked on the test photo
  against the source by eye and by size, recorded in `image-formats`. Alternatives: a JPEG fallback
  (a third of the files more for a browser that supports neither AVIF nor WebP, i.e. none we target);
  `Image` with one format (loses the 20–30 % AVIF saves).
- **Breakpoints.** `[360, 720, 1080, 1440, 1920]` as the plugin default (the cards are 358–512 px wide,
  twice that for a 2x screen); a full-bleed image passes its own list. The default list has eleven
  widths up to 3840: with two formats it would ship twenty-two files per photo.
- **Lazy by default.** `loading: 'lazy'` in the plugin; the first screen's image passes
  `loading="eager"` and `fetchPriority="high"`. Alternative: eager by default (a forgotten `lazy`
  would cost every below-the-fold photo, a forgotten `eager` one image).
- **One sprite.** Every icon, UI and feature, lives in `src/assets/icons/`, so the build emits one
  `icons-<hash>.svg`. UI icons are `fill="currentColor"`. A two-tone feature icon paints its accent
  with `var(--icon-accent, #FFD11A)` and its base with `var(--icon-base, #404040)`; the stylesheet that
  places it may set both. The logo and the brand glyphs use fixed colours.
- **Logo** is inlined by `Svg` (two colours, `class` hooks `logo__mark` and `logo__text`); the mark alone
  for the CTA is a second file. The hero decor is one raster (not 876 inline paths) through `Photo`
  with `alt=""`, rendered from the design's vectors at 2x, transparent, clipped to the hero column.
- **HTML minification.** A 30-line plugin in `vite/minify-html.js` runs `html-minifier-terser` over the
  `.html` assets in `generateBundle` (`enforce: 'post'`, build only). Alternatives: `pluginBeautify`
  (formats, does not minify); `@minify-html/node` (native binary per platform, a risk for Vercel and
  Windows alike); `htmlnano` (a PostHTML pipeline, heavier). It is a pinned dev dependency, not
  runtime, so the rule "the browser runtime has none" holds. CSS stays on Vite 8's defaults.
- **Fonts.** Static files, not variable: the design uses three weights per family, and a variable file
  carries the whole weight axis, which pays off from about four weights. Sourced from the `@fontsource`
  packages (SIL OFL), copied, the packages not kept as dependencies; the OFL notices sit next to the files.
- **Unresolved glyph.** The second counter pill of a card is a speech bubble (comments); the article page
  uses an eye (views). Both go into the sprite; the Home yellow eye is the same eye.
