## Checked against the docs

minista.dev (`plugins/image`, `guide/image`, `plugins/sprite`, `guide/sprite`, `plugins/svg`,
`guide/svg`, `plugins/beautify`, `guide/beautify`, `plugins/ssg`, `guide/images-assets`) and the installed

`adapters/vite/feature-lifecycle.js`).

- `pluginImage({ optimize, loading, decoding })`; components `Image` and `Picture` from
  `minista/assets`. `Picture` takes `formats` (the last one is the `<img>` fallback, the others
  become `<source>`s), `sizes`, `breakpoints`, `formatOptions`, `quality`; `width` and `height` are
  read from the file. Candidates larger than the source are not generated.
- `pluginSprite()` combines the SVG files of a directory into one `<dir-name>-<hash>.svg`; the file
  name is the symbol id; `Sprite` (`src`, `title`, SVG props) renders `<svg><use href=…#id/></svg>`.
- `pluginSvg()`; `Svg` (`src`, `title`, SVG props) inlines the file after SVGO; `class` and drawing
  attributes of the source are kept.
- `pluginBeautify` only **adds** indentation to the output: it is the opposite of minification. minista
  has no HTML minifier and no option for one (Vite minifies JS and CSS only).

## Decided here

- **Formats and quality.** `Photo` renders `formats={['avif', 'webp']}`: AVIF `<source>`, WebP `<img>`
  fallback, no JPEG. AVIF quality 60, WebP 78 (`formatOptions` in the plugin); checked on the test photo
  against its source (PSNR 38.3 and 37.3 dB, no visible difference at 3x), recorded in `image-formats`.
  Alternatives: a JPEG fallback (a third more files, for a browser that decodes neither format); `Image` with
  one format (gives up the 15 % AVIF saves).
- **Breakpoints.** `[360, 720, 1080, 1440, 1920]` as the plugin default (the cards are 358–512 px wide,
  twice that for a 2x screen); a full-bleed image passes its own list. The default list has eleven
  widths up to 3840: with two formats it would ship twenty-two files per photo.
- **Lazy by default, in `Photo`.** The plugin's `loading` option is meant for this but does not reach
  `Picture` in the render build (minista stays an external module there), so the component sets it. The first
  screen's photo passes `loading="eager"` and `fetchPriority="high"`. Alternative: eager by default (a
  forgotten `lazy` would cost every below-the-fold photo, a forgotten `eager` one image).
- **`type` on `<source>`.** minista writes none, so a browser without AVIF would pick the AVIF `<source>` and
  show nothing. `vite/source-type.js` adds it from the file extension. It must run in `order: 'post'`: minista
  rewrites the pages (images, sprite, SVG) in its own post hook, and an earlier plugin sees them unfinished.
- **One sprite.** Every icon, UI and feature, lives in `src/assets/icons/`, so the build emits one
  `icons-<hash>.svg`. UI icons are `fill="currentColor"`. A two-tone feature icon paints its accent
  with `var(--icon-accent, #ffd11a)` and its base with `var(--icon-base, #404040)`; the stylesheet that
  places it may set both. The logo uses the design's two colours and has the classes `logo__mark` and
  `logo__text` as hooks. Outline icons are exported as the outlined 24-grid shapes, so at 20 px the stroke is
  1.25 instead of the drawn 1.5; accepted, one symbol per icon.
- **Logo** is inlined by `Svg`; the mark alone for the CTA is a second file. The hero decor is one raster
  (not 876 inline paths) through `Photo` with `alt=""`, drawn from the design's vectors at 2x for the 1920
  layout, transparent, clipped to the hero column; the 1440 and 390 crops of the column are the section's task.
- **HTML minification: no step.** The first plan was a post plugin running `html-minifier-terser`.
  Measured on the built pages it saves 1 byte per page (21 on a page with images and icons): React writes the
  markup with no whitespace between tags and no comments, and minista adds neither. Alternatives, rejected:
  that plugin (a dev dependency with its own tree of packages for a no-op, and its whitespace collapse can
  break `white-space: pre-wrap` text); `pluginBeautify` (indents, the opposite); `@minify-html/node` (a native
  binary per platform). CSS and JS stay on Vite 8's defaults. If the output ever carries whitespace (a
  pretty-printed `<style>` in a page, say), a plugin like the one above is a ten-minute addition.
- **Fonts.** Static files, not variable: the design uses three weights per family, and a variable file
  carries the whole weight axis, which pays off from about four weights. Sourced from the `@fontsource`
  packages (SIL OFL), copied, the packages not kept as dependencies; the OFL notices sit next to the files.
  Two preloads (body and heading face): the heading is the largest text of most first screens, and a late
  swap there shifts the layout.
- **`assetsInlineLimit: 0`.** The image-bundling guide asks for it: every imported asset stays a file, so a
  small font or image is never inlined into the CSS or the HTML as a data URI.
- **Counter glyph.** The second counter pill of a card is a speech bubble (comments); the article page uses an
  eye (views). Both go into the sprite.
- **Colours off the palette.** At 1920 three feature icons are drawn in other colours; the sprite takes the
  1440 drawings, which use the two palette colours (`design-system.md` flags it).
