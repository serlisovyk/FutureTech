# Plan: the JavaScript base — `main.js` and the `Tabs`, `Disclosure`, `Toggle` widgets

Issue MY-250, branch `my-250-js-base`. No page markup changes: the widgets are added and proved
on a temporary page that is never committed.

## Scope

- `src/scripts/main.js` — the composition root and the module script tag in the layout's head.
- `src/scripts/components/` — `Tabs`, `Disclosure`, `Toggle`, by `ai/rules/oop.md`.
- `src/scripts/constants.js` — only the key names the widgets share.
- Docs: `ai/map.md` (`scripts/`), `ai/rules/oop.md` (how the JSX carries the hooks and ARIA a
  widget expects).

Not in scope: `controllers/` (no section exists yet; the folder is not created), a carousel, a
dialog, reveal animation, the `js` class on `<html>` (MY-284), any widget markup on a page.

## Decided

- One bundle, one entry `main.js` for every page: decision `page-head-and-entries`, which
  already settles the "one bundle or an entry per page" item of the issue. A page without a
  widget finds no root and does nothing.
- The tag comes together with the first real code: an empty entry is not rewritten to its
  hashed file by minista and stays a 404 in `dist/`. Checked against `minista agents`: module
  scripts in the document are handled by `pluginSsg`, no extra plugin.
- `constants.js` exists because `Tabs` and `Toggle` share the key names; breakpoints are not
  needed yet.

## Widgets

Roots and hooks are `data-*` only; roles, `aria-controls`, `aria-labelledby` are in the JSX.

| Class        | Root              | Children (inside the root)                                |
| ------------ | ----------------- | --------------------------------------------------------- |
| `Tabs`       | `data-tabs`       | `data-tab-list`, `data-tab="key"`, `data-tab-panel="key"` |
| `Disclosure` | `data-disclosure` | `data-disclosure-trigger`, `-region`, `-label` (optional) |
| `Toggle`     | `data-toggle`     | `data-toggle-button`, `data-toggle-target`                |

- `Tabs`: `start()` selects the tab with `aria-selected="true"` or the first; `select(tab)` sets
  `aria-selected` and the roving `tabindex` and shows the panel of the same key (the others get
  `hidden`). `ArrowRight` / `ArrowLeft` move and wrap (option `shouldWrap`, default on), `Home` /
  `End` go to the ends; selection follows focus. Horizontal only: the vertical orientation and
  its breakpoint are added when a design needs it.
- `Disclosure`: the trigger button owns `aria-expanded`; the region is `hidden` when closed. The
  initial state is read from the trigger's `aria-expanded`. `open()`, `close()`, `toggle()`,
  getter `isOpen`; the option `labels` (`whenOpen`, `whenClosed`) rewrites the text of
  `data-disclosure-label`. Enter and Space are the native button behavior. `hidden` rather than
  `inert`: no height animation is designed, and `hidden` also leaves the accessibility tree.
- `Toggle`: the button owns `aria-expanded`, the target is `hidden` when closed; `Escape` inside
  the root closes it and returns focus to the button. `open()`, `close()`, `toggle()`, getter
  `isOpen`; the option `labels` rewrites the button's `aria-label`. Closing on a followed link
  and the always-visible desktop state belong to the header section that uses it.
- A widget finds its children inside `root` by hooks, never from `document`; the constructor
  stores and finds, `start()` attaches listeners and renders the first state.

## `main.js`

A table `selector → class`; for each root found, `new Class(root).start()`; a missing root is
skipped. No other logic, no options. A widget that needs texts or wiring gets a controller
later, which `main.js` then lists instead.
