# Plan: the CTA block "Be Part of the Future Tech Revolution" (MY-259)

Branch `my-259-cta`. Records cited: `styles-next-to-components`, `fluid-ramps`, `path-aliases`, `ci-size-limit` (the CSS
limit may be raised here, see "Size"). minista API used: `Svg` from `minista/assets` (inline SVG through `pluginSvg`,
already enabled in `vite/parts/plugins.js`), checked against the installed package's `src/assets.d.ts` and
`plugins/svg/`. No spec: static markup and styles, nothing a user does changes beyond following a link.

## Scope

One section, one data file, one line in the layout, docs. No browser script.

- `src/data/cta.js`: `export const cta = { tag, title, text, cards }`, each card `{ id, title, text, href }`. Texts are
  the design's own: the intro is the 1920 and 1440 text (the 390 frame shortens it; the site renders the full text, as
  `ai/design-system.md` says for lists), the card texts are the 1440 and 390 wording (the 1920 frame has a longer
  second card, which wraps to three lines at 1440 and breaks the drawn card height).
- `src/sections/shared/CtaRevolution.jsx` + `CtaRevolution.css`, rendered by the layout after `<main>`.
- Docs: `ai/map.md`.

## Decided

- **A section, not a component.** The issue says "component", but `ai/rules/jsx.md` lets only sections use
  components and `ai/map.md` says the layout joins the header, CTA and footer "with their sections". The block reads
  `data/` and is used by every page, so it is `sections/shared/CtaRevolution.jsx`; the layout renders it.
- **`SectionHeading` does not fit.** It is a full-width band (fill, two borders, 120 / 80 / 40 padding) with a tag, title
  and a "View All" button. Here the tag, title and a paragraph sit beside a logo inside a band that has its own
  padding and no button. The block uses `Tag` and `Heading` (`level` 2, `size` h2) directly.
- **Landmark:** the section is a region named by its h2 (`aria-labelledby`); it sits after `<main>`, so it is not in it.
  Card titles are `<h3>` inside the links, in order under the h2.
- **Logo:** `assets/logos/logo-mark.svg` inline through `Svg`, `aria-hidden="true"`. 150 / 120 / 60 px.
- **Cards** are one `<a>` each in a `<ul>`: the title, the round arrow (decorative `Icon` `arrow-up-right`) and the text
  are inside the link, so the whole card is the click target and the base focus ring is drawn around it. The round
  arrow is a block element (`cta-revolution__arrow`): `Button` is for actions and the kit is not edited here. The Home
  hero strip draws the same arrow, so extracting it is that task's call.
- **No hover** (the design draws none; MY-284). Contrast: the intro text is Grey/50 on Dark/10 as drawn, 4.30:1, flagged in
  `ai/design-system.md` for the accessibility task.
- **Borders are inside** (author): padding is the design value minus the border width. The band has 1px top and bottom
  borders: block padding 119 / 79 / 39. The tray and each card have a 1px border: 19 / 9 / 9 and `--space-card` minus 1px.
- **Mobile composition** (design, and `width < 1024px`): the logo and the tag on one line, then the title and text, then the
  cards; `width < 768px` stacks the cards. The intro is one grid whose areas change, so the DOM order is the same.
- **Link targets (invented, no page behind the design's cards):** Resource Access `/resources`, Community Forum
  `/contact` (the only page with a way to talk to the team), Tech Events `/news`.
- **Tokens:** `--font-size-card-title`, `--space-card`, `--radius-card`, `--radius-pill` and `--border` exist; no new token,
  every other value is this block's.
