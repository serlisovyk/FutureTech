# Plan: CI on GitHub Actions and the size budget

Issue MY-255, branch `my-255-ci`. No observable behavior of the pages changes, so no spec. The
author's decisions of 2026-10-28 override the issue's "what to do": the workflow runs on every push
(no PR trigger: decision `local-merge-without-pr`), Node is 24 as on Vercel, there is no `.nvmrc`,
and the budget is `.size-limit.json` with limits by fact.

## Scope

- `.github/workflows/ci.yml` — one job, `check`, on `ubuntu-latest`.
- `size-limit` and `@size-limit/file` (exact versions), the script `size`, `.size-limit.json`.
- Docs: `ai/map.md`, `ai/rules/assets-performance.md` (the budget now exists), a record
  `ci-size-limit` and its index line.

Not in scope: a PR trigger, a matrix, more jobs, badges, required checks on `main`, the README
badge (the README arrives with the polish task), an images entry (see below).

## Workflow

`on: push`, `permissions: contents: read`, `concurrency` per ref with `cancel-in-progress`, the job
env `HUSKY: 0` (the `prepare` script must not install hooks in CI). Steps: `actions/checkout@v7`,
`actions/setup-node@v7` (Node 24, `cache: npm`; both majors exist: checkout 7.0.1, setup-node
7.1.0), then `npm ci`, `lint`, `lint:css`, `format:check`, `build`, `check`, `size`. A failing step
fails the run, so a broken `minista check` or a blown budget fails CI.

## Budget

`size-limit` 14.3.0 with the `file` plugin: it measures the built files, so `size` runs after
`build`. Measured after `npm run build`, limits rounded up to a step with small headroom:

| Entry      | Files                 | Measured  | Limit  |
| ---------- | --------------------- | --------- | ------ |
| JavaScript | `dist/assets/*.js`    | 981 B gz  | 1.5 kB |
| CSS        | `dist/assets/*.css`   | 1058 B gz | 1.5 kB |
| Fonts      | `dist/assets/*.woff2` | 111.63 kB | 120 kB |

- Fonts are already compressed: `gzip` and `brotli` are both `false`, otherwise the plugin reports
  the brotli size.
- Images: no page renders a photo yet. An empty glob makes `size-limit` fail ("can't find files",
  exit 1), so the entry is left out; the first section with a photo adds it, with its own limit.
- The limits are tight on purpose: the build is nearly empty, and each section that grows a bundle
  raises its limit in a new dated record (`ai/rules/assets-performance.md`).

## Steps

1. `build:` add `size-limit`, `@size-limit/file`, the `size` script and `.size-limit.json`.
2. `ci:` add the workflow.
3. `docs:` map, the rule, the record and its index.

- The size check bites: lower one limit locally, `npm run size` exits non-zero, restore it.
