# Plan: the footer and borders inside (MY-258)

Branch `my-258-footer`. Records cited: `styles-next-to-components`, `fluid-ramps`, `path-aliases`,
`ui-page-and-size-limits`, `ci-size-limit`; a new record `borders-inside` is added here. minista API used:
`Sprite` through `Icon` (already in the kit). No spec: behavior does not change, the footer is static markup.

## Decided (author)

- **Terms & Conditions and Privacy Policy are plain text**, not links: the site has no such pages.
- **Borders are inside, as in the design.** A block with a border has padding equal to the design's value minus the
  border width, so its outer size is the design's. Today the CSS adds the border to the padding: the outline
  `Button` is 65 px tall instead of 63. This task fixes every block on `main` that has a border, in its own commits,
  and records the rule (`ai/decisions/`, `ai/rules/css.md`).
- **No hover look** beyond what the design draws (hover is MY-284).

## Borders inside

Blocks with a border: `Button` (outline), `CounterPill`, `MetaItem` (card), `Badge`, `SectionHeading` (the band's
top and bottom lines) and the demo page `UiKit` (its group divider and panel). The avatar ring is already inside
(`border-box` on a sized image). Each padding loses the border width on that side: `Button` 18 x 24 becomes
17 x 23 at 1920, and so on through every ramp. `/ui` is measured at 1920, 1440 and 390 afterwards against
`ai/design-system.md` (outline button 63 / 49 / 49, counter pill 43 / 33 / 33, "New" badge 32 / 22 / 22).

## Footer

- **Place:** `sections/shared/Footer.jsx` + `Footer.css` (every page uses it, it composes data and kit components);
  the layout renders it after `<main>`.
- **Data:** `data/footer.js` keeps columns, legal items and the copyright text; the text loses its year, the section
  prints `©` and the year of the build. `data/socials.js` is unchanged.
- **Markup:** `<footer>` with a `.container`; one `<nav aria-label="Footer">` of five columns, each a heading (`h2`,
  its look from `.footer__title`) over a list; the bar below holds the legal texts, the social links (icon only,
  `aria-label` from the data) and the copyright. A link with `isNew` carries the kit `Badge` inside the link, so a
  screen reader hears "Resources New". The Resources column (`isButtons`) renders the kit `Button`, outline, with
  the arrow icon.
- **Kit addition:** the design's footer link button is a smaller outline button (padding 10 x 16 / 8 x 14, icon
  20 / 18 / 18, radius 8 / 6 / 6). It is the `isSmall` boolean of `Button` (`button--small`), shown on `/ui`.
- **Layout:** from 1024 px up five equal columns (gap 80 / 50 / 20), the Resources buttons stacked. Below 1024 px two
  columns with the Resources column across both, its buttons in a wrapping row. The bar is three cells (legal left,
  socials centred, copyright right) down to 768 px; below, a centred stack: socials, legal, copyright.
- **Tokens:** the footer heading is 20 / 18 / 16 like the `MetaItem` value, so `--font-size-subheading` becomes a
  token and `MetaItem` uses it; the 24 / 20 icon size is a third use (`Button`, `CounterPill`, the social icons), so
  it becomes `--size-icon`. Both in `variables.css`.
- **Hit areas:** a text link and a social icon are drawn small; each gets an invisible `::after` area (the link up to
  half the gap above and below, the icon 10 px around).

## Open points for the author (not decided here)

- **Mobile order:** the design draws Podcasts before Blogs in the 2 x 2 grid; the DOM and data order is Blogs then
  Podcasts, kept so that the focus order is the reading order. No reordering is done.
- **Contrast:** the footer links and copyright are `Dark/40` on `Dark/08` (3.21:1), flagged by the design system for
  the accessibility task; drawn as designed.
