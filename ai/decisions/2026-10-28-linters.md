# ESLint, Stylelint and a pre-commit hook; the JSX plugins; no more rule sets

Date: 2026-10-28 · Status: accepted

## Context

Agents write code in parallel worktrees; without automatic checks the style drifts within a few waves. The
repo already has Prettier for formatting and needs checks for mistakes, accessibility and the CSS rules
(`ai/rules/css.md`) that a formatter cannot see.

## Decision

- **ESLint 9, flat config:** `@eslint/js` recommended, browser globals for `scripts/`, Node globals for the
  configs, `eslint-config-prettier` last so that it never fights Prettier.
- **JSX:** `eslint-plugin-react` (`recommended` and `jsx-runtime`; `react/prop-types` is off, the project has
  no PropTypes) and `eslint-plugin-jsx-a11y` (`recommended`), only for `src/**/*.jsx`.
- **Stylelint:** `stylelint-config-standard`, class names in the BEM pattern `block__element--modifier`
  (nested selectors resolved), `color-no-hex` everywhere except the token file `src/styles/variables.css`.
- **Husky 9 + lint-staged:** the pre-commit hook runs ESLint, Stylelint and Prettier on the staged files only;
  scripts `lint`, `lint:fix`, `lint:css`, `lint:css:fix` run them over everything. The hook is never bypassed.
- Versions are exact (decision `pinned-dependency-versions`). ESLint stays on 9 because both plugins declare
  peers up to ESLint 9; lint-staged is on 16 because 17 needs a newer Node than the repo's `engines`.

## Consequences

- A commit with a lint error is rejected locally.
- Moving to ESLint 10 waits for the plugins' peer ranges, and is its own task.
- A rule beyond these is a new record (`ai/rules/scope.md`).
- Rejected: more rule sets (an import plugin, `unicorn`, strict or "all" configs; each adds noise and
  maintenance for a project this size), `--legacy-peer-deps` to take ESLint 10 (an unsupported resolution),
  separate `.eslintignore` and `.stylelintignore` files (the ignores sit in the configs).
